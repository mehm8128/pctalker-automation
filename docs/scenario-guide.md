# シナリオの書き方

シナリオの書式と、実機での試行から分かった注意点をまとめる。シナリオの例は as_test の `scenarios/<ID>/pc-talker.json`。

## 書式

シナリオは `testId`(as_test の ID。`WAIC-TEST-` を含める)、`title`、`url`(必須)、`steps` を持つ。各ステップは次を持つ。キー名は robotjs の表記。PC-Talker のショートカットキーは[マニュアル](https://pctalker.net/download/manuals/pctalker.neo/pctalker_manual.pdf)で確認する。

- `name`: ログ用のステップ名。
- `procedure`: as_info の `procedure`。同じ値のステップを 1 つにまとめて YAML に出力し、読み上げを連結する。省略すると直前のステップと同じ(同じ文を繰り返し書かない)。書き方は「as_info の procedure との対応」を参照。
- `keys`: 修飾キー→通常キーの順に押下する。
- `until`: 読み上げにその文字列が出るまでキーを繰り返す(任意、最大 10 回)。出なければ失敗扱い。
- `waitMs`: 新しい読み上げが出るまで待つ上限(既定 1500ms)。ページ遷移など遅いステップだけ増やす。
- `copy`: `false` で、キーを送って `waitMs` 待つだけにし、読み上げを取得しない。連続読み上げ(`Ctrl+Alt+K` など)の後は、取得用の `Win` キーでスタートメニューが開くため指定する。

シナリオの冒頭では、ランナーが自動で `Home`(ページ先頭への移動)を押す(ログには残さない)。

## 前提

- PC-Talker のダイレクト操作キーを ON にする。ON のとき、`H`/`U`/`V` などと、Ctrl なしの矢印・`Home`・`PageDown` が仮想カーソルの操作になる。
- ダイレクト操作キーが ON のとき、`Ctrl+↓`、`Ctrl+Home`、`Ctrl+PageDown` など Ctrl 付きの移動は効かなかった(読み上げが変わらない)。移動は Ctrl なしで書く。
- `Ctrl+Alt+J`/`R`/`M`/`F9` などの読み上げコマンドは、ダイレクト操作キーが ON でも使える。
- ブラウザーは Edge、Chrome Canary、Chrome(安定版)で確認した。Chrome はアクセシビリティを有効にする。

## 仮想カーソルのジャンプキー

マニュアル(p.38)記載。ダイレクト操作キー ON で使う。Shift を付けると前へ戻る。

- `U`/`V`: 未読/既読リンク、`H`: 見出し(`1`〜`6` でレベル指定)、`L`: 箇条書き、`T`: テーブル、`M`: ランドマーク
- `F`: フォームコントロール、`E`: エディット、`P`: ボタン、`R`: ラジオ、`X`: チェックボックス、`C`: コンボボックス
- テーブル: `T` で「N行M列の表」と読み上げられる。`Insert` でテーブルモードのオン/オフを切り替え、オンのとき矢印キーでセルを移動する(キー操作は[サイボウズ Office のマニュアル](https://jp.cybozu.help/o/ja/user/sr/commands/table.html)で確認。実機未検証)。

## 読み上げの取得

- ブラウザー上の `Ctrl+Alt+S` はページ全文のコピーになる。そのため音声ログ(`Ctrl+Alt+Win+S`)から読み上げを取得する。
- 取得するのは、音声ログ(最大 20 件)のうち、前回の取得から増えた行すべて。1 回のキー操作で複数の読み上げが出ても、全て記録される。
- 新しい読み上げが出ないステップ(同じ読み上げの再読みなど)は、`waitMs` の上限まで待って、読み上げなしで終わる。

## as_info の procedure との対応

as_info の `procedure` は、AS テストの「テスト手順(音声閲覧環境)」の単位。ただし書く内容は、テスト手順の文(「リンクを読み上げ、内容を確認」)の写しではなく、**どのキーで何をしたか**を過去の記入例の書き方で書く(例: 「Tab キーでリンク「○○」に移動した。」「H キーで次の見出しにジャンプし、確認した。」「Tab キーでセレクトメニューに移動し、Space キーで開いて、Shift+↓ キーで選択肢を変更し、Enter キーで確定した。」)。過去の例は as_info の `src/content/results/` で、同じテストの YAML を検索する。シナリオのステップは操作の単位なので、1 対 1 にはならない。

- ページ先頭への移動(`Home`)はランナーが毎回自動で行うので、シナリオには書かない。
- `procedure` は、前のステップと同じなら省略する(同じ文を繰り返さない)。同じ `procedure` のステップは 1 つの `contents` にまとまる。期待結果の項目ごと(例: 0007-02 の「選択しても何も起きない」「ボタンで遷移する」)に、操作を分ける。
- YAML への変換規則は [as-info.md](as-info.md) を参照。

## シナリオを書く前の確認

- テスト定義(as_test の `WAIC-TEST/HTML/<ID>.md`)の「テスト手順(音声閲覧環境)」と「期待される結果」を読み、手順どおりの操作(選択する、押下するなど)をシナリオに入れる。移動して読み上げを取るだけでは、手順を満たさないことがある。
- テストコード(`WAIC-CODE/WAIC-CODE-<番号>.html`)を読み、要素の数や順序をシナリオの名前・`until` に反映する。`url` の番号もテストコードと合っているか確認する(`0010-03` で別のページを指していたことがある)。
- セレクトメニューは、`Tab` で移動し、`Space` で開き、`Shift+↓` で選択を変え、`Enter` で確定する。仮想カーソル上の `↓` だけでは、選択が変わらず次の要素へ進む。

## 避けること

- **リンクの移動に `U`(未読リンク)を使わない。** ブラウザーの履歴で既読のリンクは `U` で飛ばされ、目的のリンクを通り過ぎる(w3c の `E-commerce` で発生)。既読/未読に関係なく移動できる `Tab` / `Shift+Tab`(マニュアル記載の「次/前のリンク項目へ移動」)を使う。
- **連続読み上げのコマンド(`Ctrl+Alt+K` など)の後にコピーしない。** コピー用の `Win` キーがスタートメニューを開き、以降の操作がスタートメニューに入る。`"copy": false` を指定して、キーを送って待つだけにする。
- **通り過ぎた対象を `until` で探さない。** `U`/`V` などで先へ進んだ後に、手前のリンクを `until` で探すと一致せず、上限まで Tab を押して先へ進みすぎる。`until` は、まだ到達していない対象に使う。
- 同じ読み上げになるステップを重ねない(`Ctrl+Enter` と `Ctrl+Alt+R` の併用など)。

実行時の失敗や待ち時間は [troubleshooting.md](troubleshooting.md)、as_info への出力は [as-info.md](as-info.md) を参照。
