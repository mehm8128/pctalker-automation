# シナリオ作成の注意点

実機での試行から分かったことをまとめる。`scenarios/w3c.json` が例。

## 前提

- PC-Talker のダイレクト操作キーを ON にする。ON のとき、`H`/`U`/`V` などと、Ctrl なしの矢印・`Home`・`PageDown` が仮想カーソルの操作になる。
- ダイレクト操作キーが ON のとき、`Ctrl+↓`、`Ctrl+Home`、`Ctrl+PageDown` など Ctrl 付きの移動は効かなかった(読み上げが変わらない)。移動は Ctrl なしで書く。
- `Ctrl+Alt+J`/`R`/`M`/`F9` などの読み上げコマンドは、ダイレクト操作キーが ON でも使える。
- ブラウザーは Edge、Chrome Canary、Chrome(安定版)で確認した。Chrome はアクセシビリティを有効にする。

## 読み上げの取得

- ブラウザー上の `Ctrl+Alt+S` はページ全文のコピーになる。そのため既定は `--copy log` で、音声ログ(`Ctrl+Alt+Win+S`)の最終行を読み上げとして使う。
- 取得できるのは、読み上げ 1 回分の最終行だけ。複数行にまたがる読み上げは、最後の行だけが残ることがある。
- 読み上げが前回と同じになるステップは、`waitMs` の上限まで待つ。同じ読み上げになるキーを並べると遅くなるので、重複は避ける。

## 避けること

- **連続読み上げのコマンド(`Ctrl+Alt+K` など)の後にコピーしない。** コピー用の `Win` キーがスタートメニューを開き、以降の操作がスタートメニューに入る。`"copy": false` を指定して、キーを送って待つだけにする。
- **通り過ぎた対象を `until` で探さない。** `U`/`V` などで先へ進んだ後に、手前のリンクを `until` で探すと一致せず、上限まで Tab を押して先へ進みすぎる。`until` は、まだ到達していない対象に使う。
- 同じ読み上げになるステップを重ねない(`Ctrl+Enter` と `Ctrl+Alt+R` の併用など)。

## 終わりと失敗の扱い

- 終わりの条件を設ける。最後のステップに `until` を付け、目的の読み上げが出たら終わりにする(例: コードブロックの `oxlint.config.ts`)。
- `until` は、出なければ最大 `maxRepeat` 回(既定 10)で打ち切り、`reached: false`、`pass: false` にして以降のステップを実行しない。同じ読み上げが 3 回続くと、キーが効いていないとみなして `stalled: true` で打ち切る。
- ログはステップが終わってから書かれる。ログの最後のステップの次が、止まっている(繰り返している)ステップ。

## 待ち時間

- ページ遷移(`Enter` でリンクを開く、`Home` でページ先頭へ)は、`waitMs` を 3000〜4000 にする。
- 同じ読み上げになるステップ(再読みなど)は、`waitMs` を 500 程度に短くする。

## 実行時の注意

- 実行すると `--delay`(既定 5 秒)のあいだ待つ。その間にブラウザーのページをクリックしてフォーカスを移す。
